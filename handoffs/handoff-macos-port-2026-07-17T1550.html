Deviations from the reviewed plan (recorded)

  • Seed mounts → docker cp: the installed devcontainer CLI (0.87.0) rejects readonly in --mount, so staging mounts were impossible. docker-cp seeding is strictly better (no host write-back path at all; fixes R2-2 rebuild-for-mounts without UI).
  • Library mount is now writable in containers (same CLI grammar limitation) — documented in RUNNING.md.
  • Old ticket files: filenames changed to ticket-<sessionId>.md; any pre-existing <date>-<title>.md tickets remain readable but retries no longer target them.

What went wrong / discovered en route

  • Pre-existing macOS-only test failures (path canonicalization: /home firmlink, /tmp→/private/tmp) — tests fixed to canonicalize.
  • The dual-ABI trap bit once during verification (running playwright without npm run e2e's rebuild) — behaved exactly as RUNNING.md documents.
  • Provider-smoke can't fully render claude/gemini TUIs headlessly (they need a real terminal emulator answering queries; the app's xterm.js does this). codex proved the pipeline; claude verified headless; see checklist for the 2-minute in-app checks.
  • gemini CLI hangs even headless (60s+ on gemini -p) — almost certainly stale OAuth needing interactive re-login. Not an app defect; remedy below.

Addendum (2026-07-17, post-handoff)

macOS showed the "Support Ending for Intel-Based Apps" warning for Python: the only host Python was the CLT 3.9 framework (universal bundle carrying x86_64 slices), launched by node-gyp on every electron-rebuild. Resolved by installing Homebrew Python 3.14.6 (pure arm64) — it precedes /usr/bin in both your shell PATH and the .app launcher PATH, so gyp and scripts now use it. Verified: which python3 → /opt/homebrew/bin/python3, arch arm64, electron-rebuild green. No repo change was needed.
